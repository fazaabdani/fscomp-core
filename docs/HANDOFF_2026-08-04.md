## Arsitektur final (jangan didesain ulang, lanjutkan dari sini)

```
Customer WA
  -> Fonnte (WA gateway, saat ini device tersambung ke WA PRIBADI Faza, bukan WA toko)
  -> POST /api/wa/webhook  (app/api/wa/webhook/route.ts)
       - auth: query param ?key=<FONNTE_WEBHOOK_SECRET> (Fonnte tidak kirim header apa pun)
       - lib/fonnte-client.ts: parse payload (sender/message/name/device/member),
         deteksi pesan grup lewat field "member" (langsung diabaikan, tidak masuk DB sama sekali)
  -> lib/wa-ai-orchestrator.ts: processWaIncomingMessage()
       - cek ai_enabled (kill switch) -> cek channel aktif -> rate limit (10 pesan/menit/nomor)
       - lib/wa-ai-policy.ts: decideWaAiPolicy() (otak keputusan: AUTO_REPLY/BRIDGE_AND_HANDOVER/
         HANDOVER_ADMIN/BLOCK_AI)
       - kalau AUTO_REPLY + allowSafeCatalog: lib/wa-ai-catalog-reply.ts generateWaAiCatalogReply()
         (baca stok asli via lib/wa-ai-catalog.ts, sumber sama dengan /katalog publik; persona dari
         WaAiSetting key ai_sales_persona_prompt, bisa diedit admin di dashboard tanpa redeploy;
         aturan wajib keamanan tetap hardcoded terpisah, tidak ikut bisa diubah dari UI)
  -> lib/fonnte-client.ts sendFonnteMessage() -> balas langsung ke customer
```

n8n **tidak dipakai sama sekali** untuk alur di atas (keputusan sadar — n8n cuma jadi titik gagal
tambahan tanpa nilai tambah kalau cuma jadi pipa). n8n masih dipakai untuk hal lain yang **tidak
disentuh** sesi ini: notifikasi Telegram admin (`wa-telegram-queue` di-poll n8n), 2 workflow lama
(laporan penjualan, reminder QC harian).

Endpoint lama `app/api/integrations/n8n/wa-incoming/route.ts` masih ada, sekarang cuma pembungkus
tipis ke `processWaIncomingMessage()` yang sama — dipertahankan untuk test manual lewat `curl`
(lihat `docs/WA_AI_SALES_ADMIN.md` §Test Tahap 6), bukan jalur produksi.

Follow-up otomatis: `app/api/wa/follow-up-sweep/route.ts`, dipicu **Coolify Scheduled Task**
(bukan n8n), lihat detail di file secrets.

Dokumentasi teknis lengkap & kronologis semua tahap ada di **`docs/WA_AI_SALES_ADMIN.md`** — itu
sumber kebenaran teknis utama, lebih detail dari file ini. `docs/PRD_WA_AI_CS.md` isinya histori
diskusi/keputusan, sudah agak basi di beberapa bagian (banyak ditandai "sudah tidak berlaku"),
jangan jadi acuan implementasi.

## Jebakan yang sudah pernah kejadian — supaya tidak terulang

1. **Ada 2 file `globals.css`.** `globals.css` di root repo **tidak dipakai sama sekali** (sempat
   sengaja dihapus dulu — commit `421f924` — lalu ke-upload manual lagi tanpa sengaja, sudah
   dihapus lagi di PR #27). Yang benar-benar dipakai `app/globals.css` (di-import dari
   `app/layout.tsx` baris 8, `import "./globals.css"`, resolusinya relatif ke dalam folder `app/`).
   **Kalau mau ubah CSS halaman mana pun, edit `app/globals.css`, cek dulu tidak ada file kembar.**
2. **Coolify kadang "skip build"** dengan pesan log "No build configuration changed & image found
   ... Build step skipped" walau commit-nya baru. Ini sempat jadi teori yang menghabiskan banyak
   waktu, ternyata **bukan penyebab sebenarnya** di kasus PR #27 (penyebabnya jebakan #1 di atas).
   Kalau nemu masalah "kode sudah benar tapi tidak keliatan di production" lagi: **cek dulu apakah
   editnya kena file/import yang benar**, baru curigai Coolify/cache.
3. **Terminal bawaan Coolify (menu "Terminal") sering putus koneksi** ("websocket connection lost")
   — sudah lama begitu (bukan cuma sesi ini). Jangan andalkan itu untuk debug server. Pakai SSH
   langsung (lihat file secrets) — PC Faza sudah tersambung Tailscale ke server, jadi bisa diakses
   langsung tanpa VPN tambahan.
4. **Worktree `...\work\fscomp-core-github`** (folder sebelah `fscomp-core-audit-20260621`) **punya
   kerjaan belum di-commit** untuk fitur "servis" yang tidak terkait (`app/servis/`,
   `lib/service.ts`, migration `202606190001_service_tickets`). **Jangan disentuh/dihapus** tanpa
   konfirmasi Faza — kemungkinan itu kerjaan Codex/developer lain yang belum selesai.
5. **Jangan push commit baru ke branch yang sudah di-merge** dan berharap otomatis masuk `main` —
   itu penyebab PR #26 harus dipisah dari #25 (commit terlambat tidak ikut ter-merge). Kalau PR
   sudah di-merge, branch baru dari `origin/main` lagi untuk kerjaan berikutnya.

## Bug yang ditemukan dari tes langsung (sudah diperbaiki di PR #30)

Faza test kirim pesan ke WA AI, dapat respons aneh — AI kasih jawaban katalog yang benar sekali,
tapi begitu customer bilang "Saya Mba Mba bukan Mas" (koreksi sapaan), AI selamanya cuma balas
template "Siap nggih, saya teruskan ke admin..." untuk SEMUA pesan berikutnya, termasuk pertanyaan
normal seperti "Stok yang ready apa saja?" dan "Budget saya 3 jutaan". Akar masalah: kalimat yang
tidak cocok kata kunci apa pun dianggap "tidak aman" dan mengunci status percakapan secara permanen.
Detail lengkap di `docs/WA_AI_SALES_ADMIN.md` §Tahap 11.

**Yang masih perlu dicek Faza setelah baca ini:** percakapan yang macet di tes itu perlu diklik
**"Kembalikan ke AI"** manual di dashboard `/wa-ai` (fix-nya tidak retroaktif ke percakapan yang
sudah kadung macet), baru dites ulang dari awal untuk konfirmasi PR #30 benar-benar menyelesaikan
masalahnya.
