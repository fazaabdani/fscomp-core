# Audit Bug Menyeluruh — Sistem Core (19 Agustus 2026)

Audit dilakukan atas permintaan eksplisit: cek semua fungsi di sistem Core, cari semua bug
satu-persatu, sedetail mungkin. Dikerjakan lewat 7 review paralel per area fitur, tiap area
dibaca penuh isi filenya (bukan sekadar grep).

**Update 19 Agustus 2026 (sore):** semua temuan sudah diperbaiki dan di-push, termasuk S6/C15
(keputusan owner: batasi harga modal ke admin saja). 4 item race condition kecil sengaja
dibiarkan (C10, C11, C16, C17) karena risikonya rendah dan perbaikan penuhnya tidak proporsional
dengan dampaknya — detail alasan ada di catatan masing-masing.

Status: `[x]` sudah diperbaiki, `[ ]` belum/sengaja dilewati (lihat catatan).

## KRITIS (5) — prioritas perbaikan tertinggi

### K0. [x] BARU DITEMUKAN — CSS transform di `PageTransition` merusak SEMUA elemen `position: fixed` se-situs
Ditemukan saat investigasi laporan "filter & urutkan di mobile ada bug". `app/PageTransition.tsx`
membungkus SETIAP halaman dalam div beranimasi `translateY(8px)→0` dengan `animation-fill-mode:
both` — akibatnya transform itu **menempel permanen** di div itu walau animasi 180ms-nya sudah
selesai. CSS: elemen dengan `transform` aktif jadi containing-block untuk descendant
`position:fixed`, jadi SEMUA drawer/modal/lightbox di seluruh situs (bukan cuma katalog) jadi
salah posisi — tidak benar-benar "fixed" ke viewport. Dikonfirmasi lewat inspeksi live browser
mobile ke core.fscomp.id (drawer filter punya `transform: matrix(...362px...)` padahal harusnya
`translateX(0)`, dan bounding box setinggi 13.800px alih-alih tinggi viewport).
**Diperbaiki:** hapus `transform` dari keyframe animasi, sisakan fade opacity saja.

### K1. [x] Stok Kajen bisa hilang total dari katalog publik
**File:** `lib/catalog-page-data.ts` (`getCatalogPageData`)
Query katalog pakai `orderBy: [{stockLocation:"desc"}, ...]` + `take: 120` diterapkan **sebelum**
dipisah per lokasi. Karena "WIRADESA" > "KAJEN" secara alfabet, begitu unit ready di Wiradesa
≥120, seluruh unit Kajen tidak pernah ikut ter-fetch.
**Diperbaiki:** fetch terpisah per lokasi (masing-masing cap 120), lalu digabung. Fix yang sama
juga diterapkan di `lib/wa-ai-catalog.ts` (rekomendasi AI WhatsApp punya pola bug identik).

### K2. [x] Race condition duplikasi transaksi penjualan (request konkuren)
**File:** `app/sales/actions.ts`
Cek "unit sudah ada sale aktif" dilakukan di luar `$transaction` — menutup double-klik tapi tidak
menutup dua request beneran bersamaan. Index unik `Sale_unitId_key` pernah ada lalu di-drop untuk
mendukung re-jual unit yang di-void, tanpa pernah diganti proteksi setara.
**Diperbaiki:** migration baru `prisma/migrations/202608190001_sale_active_unit_unique` — partial
unique index `WHERE "voidedAt" IS NULL`. `createSaleAction` & `restoreSaleAction` sekarang
menangkap error unique-constraint (P2002) dan redirect rapi ke nota yang sudah ada, bukan crash.
**PENTING:** migration ini perlu benar-benar jalan di production (`npx prisma migrate deploy`
via Pre-deployment Command Coolify, atau manual SSH kalau pre-deploy command gagal seperti
kejadian sebelumnya) — kalau tidak, proteksi DB-nya belum aktif meski kode sudah benar.

### K3. [x] Upload foto di halaman Media Library kemungkinan gagal untuk foto ukuran normal
**File:** `next.config.js`
Next.js 14.2.5 membatasi body Server Action ke default 1 MB. Foto HP 2-10MB akan ditolak.
**Diperbaiki:** set `experimental.serverActions.bodySizeLimit: "15mb"`.

### K4. [x] Penomoran unit hasil import spreadsheet bisa tabrakan/crash
**File:** `app/batch-psi/import/actions.ts`
Nomor unit baru dihitung dari `COUNT(*)`, bukan MAX — kalau ada unit yang pernah dihapus dari
batch, re-import bisa tabrakan nomor dan crash 500 di tengah loop tanpa transaction.
**Diperbaiki:** hitung dari nomor urut MAX yang ada, bungkus loop dalam `$transaction`, tangkap
unique-constraint error dengan redirect pesan jelas (`?error=nomor-unit-bentrok`).

## Bug tambahan yang dilaporkan user (mobile katalog filter & urutkan)

di kode katalog. Sudah diperbaiki bersamaan.

## Catatan tambahan (bukan bug per se, worth diketahui)
- Banyak fungsi `lib/*-page-data.ts`/`lib/*-data.ts` menangkap **semua** jenis error dan fallback
  ke data demo/null secara diam-diam — bisa menyamarkan masalah koneksi DB sungguhan. Pola
  berulang di banyak tempat, bukan 1 bug tapi kebiasaan arsitektur — belum disentuh sesi ini.
- `canChangeDailyQcStockLocation` sempat terlihat seperti bug (izinkan semua role) tapi
  dikonfirmasi lewat riwayat git memang disengaja bertahap — bukan bug.
